# Released datasets

Three layers, with different provenance:

- **`curated/` and `analysis_input/` are deterministic projections** of the final analysis master
  used to produce the manuscript. No table in these two layers was hand-assembled, and no row was
  added, removed, reordered or altered by the projection.
- **`analysis_data/` holds derived results** — operational units, evidence tiers, network layers and
  frozen trees produced by the analysis code or by the frozen upstream pipelines.
- **`external_evidence/` holds manually curated evidence** — records assembled by hand from EPPO,
  FAO-IPPC, ICTV and primary literature, published with their full provenance chain.

```
curated/           reader-facing datasets — one row per sequence / per association
      │  field projection: only the fields the final analysis code reads
      ▼
analysis_input/    minimal analysis-ready inputs read by analysis/
      │
      ├────────────────────────────┐
      ▼                            ▼
analysis_data/                external_evidence/
derived layers (clusters,      manually curated records
evidence, networks, trees)     + their provenance
```

`supplementary/` (outside this directory) holds the frozen submission products, Data S1 —
Tables S1–S5, provided verbatim and not regenerated by the release code.

Digests for every file are in `../checksums/SHA256SUMS.txt`.

## `curated/` — reader-facing datasets

| File | Rows | Cols | Contents |
|---|---|---|---|
| `plant_virus_sequence_dataset.tsv.gz` | 80,028 | 18 | One row per virus sequence. |
| `virus_host_association_dataset.tsv.gz` | 83,034 | 33 | One row per virus–host association. |

The association table is the base analytical unit of the paper: a sequence may carry several
associations when it is reported from more than one host, and every host-range statistic is computed
over associations.

These two tables are the reader-facing release and are kept exactly as the frozen release build
produced them, including their field names. `analysis_input/` below carries the same records under
the field names the analysis code uses.

### Key fields

**Identity**

| Field | Meaning |
|---|---|
| `sequence_id` | Stable identifier for one sequence record. Join key between the two tables. |
| `source_record_id` | *(association table only)* Identifier of the association record in the source database. |
| `association_row_n` | *(sequence table only)* How many association rows the sequence carries. |

**Virus taxonomy** — `virus_taxid`, `virus_realm`, `virus_kingdom`, `virus_phylum`, `virus_class`,
`virus_order`, `virus_family`, `virus_genus`, `virus_species`

Formal, current taxonomy anchored to the NCBI Taxonomy identifier in `virus_taxid`. `virus_species`
follows ICTV species nomenclature where an ICTV species exists.

| Field | Meaning |
|---|---|
| `genome_type` | Nucleic-acid / genome class of the virus. |
| `sequence_length_nt` | Sequence length in nucleotides. |

**Operational virus units** — the units the paper actually counts viruses in

| Field | Meaning |
|---|---|
| `vc80_final_id` | **VC80** — operational virus unit defined by 80% nucleotide clustering. Used wherever a "virus" must be counted without relying on taxonomy being complete. The released universe resolves to 11,708 VC80 units; see the note below for how `vc80_final_id` relates to that count. |
| `rdrp65_unit_id` | **RdRP65** — parallel operational unit for RNA viruses, defined on the RdRP marker at 65% amino-acid identity. 27,549 sequences are assigned to 1,700 RdRP65 units. Used as the taxonomy-free robustness check throughout. |
| `arthropod_sequence_supported` | Whether the sequence carries arthropod-associated sequence evidence (the union of the S0–S2 evidence tiers; see `analysis_data/arthropod_*`). |
| `arthropod_evidence_codes` | Which evidence tiers support the assignment above. |

> **`vc80_final_id` and VC80 counting.** `vc80_final_id` — Identifier assigned during the initial 80%
> nucleotide clustering. The curated and analysis-input tables retain all 11,744 initial cluster IDs so
> that the consistency filtering can be reproduced. After excluding 36 clusters with inconsistent
> virus-family or genome-type annotations, the remaining 11,708 clusters are defined as VC80
> throughout the manuscript.

**Host taxonomy** *(association table)* — `host_taxid`, `host_taxonomy_current_rank`,
`host_phylum`, `host_class`, `host_order`, `host_family`, `host_genus`, `host_species`

Complete, current host lineage anchored to `host_taxid`. Only records with a complete lineage can
contribute to host-phylogenetic-distance statistics.

**Geography** *(association table)* — `country`, `continent`

Resolved, standardised geography for the association.

**Source provenance** — `source`

Which upstream database each record came from, as a single provenance class:
`NCBI Virus only`, `Virus–Host DB only`, `NCBI Virus + Virus–Host DB`, or
`Land Flora RNA virome`. A record that appears in more than one database is reported once, under the
combined class.

**Land Flora records** *(association table)* — `landflora_record_id`, `landflora_new_virus_id`,
`landflora_evidence_tier`, `landflora_strict_plant_infection`, `landflora_host_resolution_rank`

Fields specific to the Land Flora RNA virome survey: the source record, the putative new virus it was
assigned to, the evidence tier supporting it, the host taxon rank the record could be resolved to, and
whether it meets the strict plant-infection criterion.

`landflora_strict_plant_infection` is used for the **strict plant-infection sensitivity analysis**;
it does not by itself decide whether a record enters the main analysis, where other Land Flora
evidence tiers also contribute.

> **A note on Land Flora taxonomy.** Some Land Flora RNA virome records lack a current ICTV
> taxonomic anchor; formal virus taxonomy fields for these records are therefore intentionally left
> blank rather than being filled with provisional source-study classifications.

**No nucleotide or protein sequence payload is included.** These tables carry metadata, accessions,
taxonomy and provenance only, which is why the whole release can be hosted directly on GitHub. To get
back to sequences: records from NCBI Virus and Virus–Host DB can be retrieved by accession from NCBI;
Land Flora records are identified by their source-study record identifiers and are available from the
published Land Flora RNA virome data (see `../docs/EXTERNAL_INPUTS.md`).

```r
data.table::fread("data/curated/plant_virus_sequence_dataset.tsv.gz")
```

## `analysis_input/` — what the code actually reads

Column-minimal projections of the curated tables, containing exactly the fields the final analysis
code depends on and nothing else. These are the files `analysis/` opens by default.

| File | Rows | Cols |
|---|---|---|
| `sequence_analysis_input.tsv.gz` | 80,028 | 18 |
| `association_analysis_input.tsv.gz` | 83,034 | 30 |

They carry the same records as `curated/`, restricted to the fields the final code reads and named as
the code names them (`rdrp65_unit_id` becomes `rdrp_operational_cluster_id`; the single `source`
class is carried as `source_label_4way` plus `source_LandFlora`, the two forms the analyses consume).
Use `curated/` to read the data; use `analysis_input/` to check precisely what the analyses were
computed from.

### `analysis_data/phylogeny/` — frozen trees

Shipped as *derived inputs*, so that no alignment, model selection or tree search is needed to
reproduce the phylogenetic results.

| Path | Contents |
|---|---|
| `twelve_family/trees/<family>/<family>.treefile` | Final maximum-likelihood tree for each of the **12** focal families: Geminiviridae, Caulimoviridae, Alphaflexiviridae, Betaflexiviridae, Closteroviridae, Mitoviridae, Partitiviridae, Potyviridae, Rhabdoviridae, Secoviridae, Solemoviridae, Tombusviridae. The marker used per family (RdRp, replicase, CP, etc.) is recorded in `03K_D_tree_input_manifest.tsv`. |
| `twelve_family/AA95_membership/<family>[.Rep_conserved].AA95_membership.tsv` | AA95 cluster membership: which sequences each tree tip represents. Geminiviridae carries the `.Rep_conserved` infix because it uses the dedicated Rep-conserved marker pipeline. |
| `twelve_family/final_alignment/<family>[.Rep_conserved].final_alignment.faa` | The exact filtered amino-acid alignment the published tree was inferred from. |
| `twelve_family/source_alignment/<family>[.Rep_conserved].AA95.*.filtered.faa` | The upstream alignment before the family-specific final trimming step. |
| `twelve_family/tree_tip_host_spectrum/<family>.tree_tip_host_spectrum.tsv` | Per-tip host spectrum: representative sequence, cluster member count and the set of hosts behind each tip. Read directly by `03L_FINAL_run_one_family.R`. |
| `twelve_family/03K_D_tree_input_manifest.tsv` | Provenance record: per-family marker, input alignment, tip count and eligibility rule. The three file-path columns are **relative to this directory**. |
| `twelve_family/03K_D_final_eligibility_FROZEN.tsv` | Frozen per-tip eligibility decisions shared by every downstream phylogeny step. |
| `twelve_family/03K_D_tree_QC.tsv` | Tree QC output (tip recovery, tree length, support summary). |
| `twelve_family/03E_tree_pipeline_manifest.tsv` | Marker choice, raw marker count, nr95 count, filtered tip count and alignment length for the four families built first. |

A per-tip alignment QC table also exists for every family (`06_AA95_alignment_QC/<family>/<family>.alignment_sequence_QC.tsv`
in the analysis tree); the release keeps the four that were already public under
`twelve_family/<family>.alignment_sequence_QC.tsv` and the rest are regenerated by `03C`.

**Two tree-building routes.** The 12 families are not all built the same way, and the release reflects
this. Ten RNA families go through `03I_build_one_RNA_family_tree.sh`, whose `FAMILIES` array covers
Potyviridae, Betaflexiviridae, Secoviridae, Tombusviridae, Rhabdoviridae, Solemoviridae,
Partitiviridae, Closteroviridae, Mitoviridae and Alphaflexiviridae. The DNA families go through the
`03K` route, and Geminiviridae has its own conserved-region branch
(`03K_C3_extract_Geminiviridae_Rep_conserved.py` → `07_Geminiviridae_Rep_conserved/`). `03L_FINAL_run_one_family.R`
switches between them at run time. A tree from the four-family era therefore cannot stand in for the
twelve-family set, which is why the old `four_family/` directory was replaced rather than extended.
| `TSWV/{L,M,S}.treefile` | Final segment trees for the TSWV case study. |
| `TSWV/LMS_matched_isolate_metadata.tsv` | Isolate metadata matched across the three segments. |
| `TSWV/07M_LMS_segment_tree_manifest.tsv` | Provenance record for the three segment trees. |

Alignments, bootstrap replicates, intermediate logs and model files are **not** included — they are
only needed to rebuild the trees, which is outside the reproducibility scope. (`*.mldist`,
`*.ckp.gz` and `*.splits.nex` are deliberately excluded because they are large, machine specific and
regenerable from the alignments.)

## `external_evidence/` — curated external records

| File | Rows | Cols | Contents |
|---|---|---|---|
| `prioritized_genera_evidence_summary.tsv` | 12 | 7 | One row per prioritised genus: vector status, transmission mode, regulatory / economic records. |
| `prioritized_genera_evidence_sources.tsv` | 28 | 9 | One row per **individual evidence item**: genus, claim, source type, source title/identifier, public URL, and verification status (which carries the check date). This is the audit trail — keep it attached to the table above. The two former columns naming the author's internal archive document and its page ranges were dropped for the public release; every row keeps a public URL, so nothing lost its point of origin. |
| `candidate_external_evidence.tsv.gz` | 12 | 38 | Traceable evidence matrix for the 12 final candidate genera. |

These tables are human-curated from EPPO, FAO-IPPC, ICTV and primary literature, not derived
automatically, and are published with their full provenance chain so every assertion can be traced
back to a source document. `candidate_external_evidence.tsv.gz` covers exactly the 12 genera that
appear in the final Results 3.6 panel.

## What is deliberately not redistributed

| Resource | Why absent | Consequence |
|---|---|---|
| NCBI Virus, Virus–Host DB and Land Flora raw dumps | third-party, versioned | NCBI records can be re-downloaded by accession; every accession used is listed in the curated tables. Land Flora records are available from the published source-study data. |
| VIPDB raw workbook | third-party | `analysis_data/VIPDB_*` already carry the normalised result; the raw file is needed only to re-run `04A_VIPDB_normalize.R`, which falls back to the released normalised outputs when it is unavailable. |
| TSWV source GenBank flat file | third-party | Core statistical analyses and phylogenetic summaries are regenerable from the released inputs. Gene-level TSWV recombination and selection outputs are provided as frozen derived results; rebuilding these analyses requires the external inputs documented in `../docs/EXTERNAL_INPUTS.md`. |
| Pfam-A.hmm, GenBank flat files, Arthropoda reference FASTA | third-party binaries / bulk sequences | Needed only by the optional `pipeline/` scripts. |

See `../docs/EXTERNAL_INPUTS.md` for how to obtain each one.
