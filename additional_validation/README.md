# `additional_validation/` — NOT_IN_PAPER

Everything under this directory is **not reported as a result in the manuscript**.
It is released so a reader can see that the descriptive transmission-lineage
aggregation used in Results 3.4 / Table S3 section I was checked against the
obvious alternative explanation, and that the alternative does not change any
published statement.

| subdirectory | status | what it contains |
|---|---|---|
| `transmission_mode_consistency/` | `NOT_IN_PAPER` | Virus genus / family mode-consistency tabulation, and a vector-species specificity control testing whether "the same insect" adds predictive information over virus lineage alone. |

## Why it is kept separate

The manuscript reports that **transmission mode is strongly aggregated within
virus lineage** (Results 3.4; `supplementary/Table_S3_Arthropod_vector/S3I_vector_family_by_virus_genus.tsv`,
generated by `analysis/03_arthropod_transmission_ecology/analysis/04D_transmission_biology_extended_v3.R`).
That descriptive statement *is* in the paper and stays in the main module.

The specificity control below goes further and asks whether vector identity
improves *prediction* once virus lineage is known. Its answer (no improvement on
the shared target set) is a consistency check on the descriptive statement, not a
result claimed in the manuscript. It is therefore not listed among the README
headline findings and must not be cited as a manuscript result.

## Inputs

The original input was `VIPDB_relation_raw.xlsx`, a third-party workbook that is
**not redistributed** here (see `docs/EXTERNAL_INPUTS.md`).

This control now runs on the released
`data/analysis_data/VIPDB_relation_normalized.tsv.gz`, a normalized projection of
the same workbook. That table already carries `fine4_mode`, `virus_taxid`,
`virus_genus`, `virus_family`, `vector_taxid` / `vector_name` and
`vector_genus`, i.e. every field the control consumes, so no third-party file is
needed to reproduce it.

## Reproduce

```bash
# from this directory
bash run_specificity_control.sh
```

or explicitly:

```bash
Rscript 04D_transmission_specificity_control.R \
  <repo>/analysis \
  <repo>/data/analysis_data/VIPDB_relation_normalized.tsv.gz
```

Output is written next to the script (override with `SPECIFICITY_OUTDIR`).
Runtime is about 1 minute on one core; the strict-rule loop is O(pairs x schemes).

## What the control shows

Under the strict rule (>= 2 training viruses in the grouping, unanimous dominant
mode), read from `04_incremental_vector_value.tsv`:

| baseline | conditioned | common target n | baseline acc. | conditioned acc. |
|---|---|---|---|---|
| virus genus only | vector species x virus genus | 365 | 1.000 | 1.000 |
| virus genus only | vector genus x virus genus | 375 | 0.997 | 0.997 |
| virus family only | vector species x virus family | 347 | 1.000 | 1.000 |
| virus family only | vector genus x virus family | 356 | 0.997 | 0.997 |

Virus lineage alone already predicts the four-class transmission mode almost
perfectly; adding vector identity costs coverage without raising accuracy. This is
exactly why the descriptive aggregation in the paper is presented as a
lineage-level property, not as evidence that vector identity carries extra
information.
